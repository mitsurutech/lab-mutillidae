# Docker Compose で動く OWASP Mutillidae II ラボ：わざと脆弱にした PHP の Web アプリで SQL インジェクション、XSS、LDAP インジェクションを練習する

[English](README.md) | [Français](README.fr.md) | [日本語](README.ja.md) | [Español](README.es.md)

[![check](https://github.com/mitsurutech/lab-mutillidae/actions/workflows/check.yml/badge.svg)](https://github.com/mitsurutech/lab-mutillidae/actions/workflows/check.yml)

授業でそのまま使える **Web アプリケーションセキュリティのラボ**です。学校やカレッジが生徒一人ひとりに専用のデータベース、コンテナ、ブラウザー上のターミナルを渡せる [MitsuruTech ラーニングプラットフォーム](https://mitsurutech.co.uk/ja/learning)で提供しています。生徒にはそれぞれ **OWASP Mutillidae II** の専用コピーが渡されます。わざと安全でなくしてある PHP のサイトで、**MariaDB データベース**と **LDAP ディレクトリ**もすでに用意されています。**SQL インジェクション、クロスサイトスクリプティング、コマンドインジェクション、LDAP インジェクション**などを OWASP Top 10 全体にわたって練習でき、セキュリティレベルを切り替えると、対策ごとに何が変わるかがわかります。生徒は脆弱性を説明し、証拠を提出します。何もインストールせず、他の人のマシンに害が及ぶこともありません。

ファイルは `docker-compose` ファイルの `compose.yaml` 1つで、自分のマシンでもプラットフォームでも同じように動きます。プラットフォームでは、生徒ごとにインターネットへの出口がない専用のコピーが使えます。

## たった1つのルール

**攻撃してよいのは自分のコピーだけです。** このラボのものはすべて自分専用のコピーの中で動いており、インターネットへの経路も他の生徒への経路もありません。そのため、手が届くのはラボが起動したアプリケーションだけです。自分のものではない Web サイト、ネットワーク、マシンに対しては、ラボでもそれ以外でも、決してツールを向けないでください。英国では、それは[コンピューター不正使用法 1990（Computer Misuse Act 1990）](https://www.legislation.gov.uk/ukpga/1990/18/contents)に違反する犯罪で、ほとんどの国に同様の法律があります。弱点の仕組みを学ぶことは、弱点のないソフトウェアを作ることにつながります。授業の最初の話題には、このルールがなぜあるのか、責任ある開示とはどういうものか、がよいでしょう。

## 中身

| サービス | イメージ | メモリ | 内容 |
| --- | --- | --- | --- |
| `www` | [`webpwnized/mutillidae:www-2.12.7`](https://hub.docker.com/r/webpwnized/mutillidae) | 512 MB | Mutillidae を動かす Apache と PHP。開くサイトです |
| `database` | `webpwnized/mutillidae:database-2.12.7` | 384 MB | Mutillidae がアカウント、ブログ、ログを保存する MariaDB データベース |
| `directory` | `webpwnized/mutillidae:ldap-2.12.7` | 256 MB | LDAP の演習が読む OpenLDAP ディレクトリ |

各イメージはバージョンタグとダイジェストの両方で固定してあるので、同じタグで再ビルドされても、授業中のラボが変わることはありません。3つ合わせて 1152 MB までに制限され、アイドル時は約 210 MB を使います。ラボはノート PC で約10秒で使えるようになります。データベースは自動で作られます。データベースが立ち上がってから、ラボが Mutillidae 自身のセットアップページに作成を依頼し、そのあとで初めて準備完了と表示します。つまり「準備完了」は、サイトが動いていて、初回起動の警告ページをクリックして進む必要がないことを意味します。

イメージはサードパーティのプログラムで、プロジェクト自身の公開イメージを無変更で実行しています。ここでは何もビルドせず、このリポジトリのものがイメージの中で配布されることもありません。64 ビットの Intel と AMD のマシン（amd64）向けに公開されており、プラットフォームもそれで動いています。Apple シリコンのノート PC では Docker がエミュレーションで実行するので、動きますが遅くなります。

## 自分のマシンで動かす

Compose プラグイン付きの Docker が必要です。初回の起動でイメージをダウンロードします。イメージは大きく、ダウンロードはそれぞれ約 250 MB、130 MB、90 MB です。

```bash
docker compose -f compose.yaml -f local.yaml up
```

<http://localhost:8080> を開きます。

`local.yaml` はポートを `127.0.0.1` だけに公開するので、ラボには自分のコンピューターからだけ到達でき、ほかのどこからも到達できません。`Ctrl-C` で止め、`docker compose -f compose.yaml -f local.yaml down -v` で削除します。攻撃してもかまわないマシンで動かしてください。アプリケーションはわざと安全でなくしてあります。

## 取り組み方

1. **サイトを開く。** データベースはすでにできているので、設定は不要です。どのページの上部にも、セキュリティレベル（最初は 0）とヒントが有効かどうかが表示されます。
2. アカウントが必要なページには、パスワード `adminpass` で `admin` として**ログイン**するか、**Login/Register** のページで自分のアカウントを作ります。
3. **演習を選ぶ。** 左のメニューは OWASP Top 10 で、その下に弱点が並んでいます。SQL インジェクション（データの取り出し、認証の回避、ブラインド、時間差）、HTML と JavaScript のインジェクション、コマンドインジェクション、LDAP インジェクション、クロスサイトスクリプティング、ファイルインクルージョン、弱いセッションなどです。**Toggle Hints** を押すと、各ページにヒントが表示されます。
4. **レベルを上げる。** メニューの **Toggle Security** で 0 から 1、そして 5 へ進み、また 0 に戻ります。同じ演習をもう一度やってみてください。レベル 0 で40件のアカウントすべてを見つける入力が、レベル 5 では1件も見つけられなくなり、対策ごとに何が変わるかがわかります。
5. **いつでもやり直せる。** ラボを停止してから起動し直すと、メニューの **Reset DB** と同じく、新しい Mutillidae になります。

## 教員向け

このラボには自動採点するものはありません。生徒が証拠を提出し、ほかのラボと同じように教員が採点します。

**証拠は2つに分けて求めてください。** 1つめは作業の証明です。解いた演習ごとのスクリーンショットで、ブラウザーにラボ自身のアドレスが写っていて、本人のコピーだとはっきりわかるものです。2つめは理解です。演習ごとに、脆弱性とは何か、使った入力そのものとそれが通った理由、攻撃者がそれで何をできるか、コードをどう書くべきだったかを、自分の言葉で書いた説明です。2つめで、理解したのか、解説のコピーなのかがわかります。より発展的な課題では、同じ演習をレベル 5 でも行い、コードが何を変えているかを求めてください。

**コースの中での位置づけ。** Mutillidae は Web アプリケーションセキュリティとセキュアコーディングの入門に向いています。レベルの違う同じ演習は同じページで、安全でない状態と修正後の状態を見られるからです。入力の検証、出力のエンコード、パラメーター化クエリ、認証を扱えます。単元の法律と倫理の面も支えます。認可と範囲、コンピューター不正使用法 1990、責任ある開示です。正確な文言はご自身の認定機関の単元でご確認ください。ここでは引用していません。

**誰が何を見るか。** こうしたラボは16歳と17歳の生徒に使われることが多くあります。コピーは、起動した生徒本人だけのものです。そのモジュールを教える教職員は、生徒が何をしたかを見るためにコピーを開くことができ、生徒の作業を開くとアクセスログに記録されます。このログは生徒本人が読めます。

## ラボでできないこと

ラボにはインターネットへの出口がまったくないので、Mutillidae の中で別の Web サイトからページを取得したり、インターネットで名前を引いたりするものは、到達する先がありません。生徒に開かれるのは Web ポートだけで、データベースとディレクトリは開かれませんが、ラボの隣のターミナルからは、すべてのサービスを名前（`www`、`database`、`directory`）で参照できます。サイトには 512 MB、データベースには 384 MB、ディレクトリには 256 MB が割り当てられます。

## トラブルシューティング

- **「起動」の直後にサイトが表示されない。** 数秒待ってからもう一度「開く」を押してください。ラボは、データベースが作られてから初めて準備完了と表示します。
- **サイトがデータベースの不具合を表示する。** ラボを停止してから起動し直して新しいコピーにするか、メニューの **Reset DB** を選んでください。
- **自分のマシンでポート 8080 がすでに使われている。** `local.yaml` の左側の数字を、たとえば `127.0.0.1:8081:80` のように変えて、そのポートを開いてください。

## ラボの検査

`test/check.sh` は、プラットフォームのランナーが各サービスを起動するのと同じ方法でラボを起動し（すべての capability を外し、`no-new-privileges`、プロセス数の上限、メモリの上限を設定し、インターネットへの出口なし）、そのネットワークの内側から、このページが約束していることを確かめます。サイトが応答すること、admin がログインできること、注入した名前がレベル 0 ではすべてのアカウントを見つけ、レベル 5 では1件も見つけないこと、ディレクトリが動いていることです。Docker が必要で、push のたびに実行されます。それが先頭のバッジです。

```bash
test/check.sh
```
